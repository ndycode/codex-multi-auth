# v2.9.2

A maintenance release. Nothing in the installed package behaves differently from 2.9.1: no runtime, CLI, or configuration changes. What this fixes is a repository tooling gate that failed on every clean checkout.

```bash
npm i -g codex-multi-auth
```

## What was wrong

**`npm run typecheck:scripts` failed on any checkout that had not been built.**

`scripts/codex-multi-auth.js` reaches the CLI through `await import("../dist/lib/codex-manager.js")`, and `tsconfig.scripts.json` typechecks that file with `checkJs`. `dist/` is generated and gitignored, so after a fresh `git clone && npm ci` the compiler had nothing to resolve and stopped:

```
scripts/codex-multi-auth.js(56,48): error TS2307: Cannot find module
'../dist/lib/codex-manager.js' or its corresponding type declarations.
```

Three CI jobs run that script, and the local gate documented in `CONTRIBUTING.md` did not list it, so a contributor could only hit the failure by running the script directly and had no documented reason to.

## What's fixed

**The build is part of the script.** `typecheck:scripts` is now `npm run build && tsc -p tsconfig.scripts.json`, matching every other script here that consumes generated output: `pack:check`, `coverage`, `bench:runtime-path` and `generate:schema` all begin the same way. One place covers all three CI call sites, a clean local checkout, and any job added later.

`CONTRIBUTING.md` now lists `npm run typecheck:scripts` in the documented local gate, since it works from a clean tree.

## Under the hood

The `validate` workflow job drops a build step the script change made redundant, so per-job compile counts are unchanged. `test/ci-workflows.test.ts` derives its build-ordering guard over every job in `ci.yml` rather than a hardcoded pair, and reads steps by YAML key position instead of raw string offsets, so a commented-out or `if:`-guarded build step no longer satisfies it.
