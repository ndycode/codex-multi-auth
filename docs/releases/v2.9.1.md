# v2.9.1

A `--cost` budget can no longer be quietly defeated by the models most worth capping, refreshing one account from the login dashboard stops disturbing the others, and `login` gains a way to re-authenticate a single saved account. Nothing to migrate — install and go.

```bash
npm i -g codex-multi-auth
```

## What was wrong

**A `--cost` budget was still unenforceable for the priciest models.**

2.9.0 made cost and token budgets work for the first time, and shipped with a known limitation: the price table did not cover every model this package routes, so requests to the uncovered ones priced at zero. The gap was worse than it read. Eight of the fifteen model ids the router normalizes to have no rate — `gpt-5.4-pro`, `gpt-5.5-pro`, `gpt-5.2-pro`, `gpt-5.4-mini`, `gpt-5.4-nano`, `gpt-5-mini`, `gpt-5-nano`, `gpt-5.1` — and that list is every `pro` tier, which is to say the models a spend cap exists to protect you from.

An unpriced request records its token counts correctly and prices at `null`. The ledger sums cost as `costUsd ?? 0`, so the row contributes `$0.00`, and the guard compares that total against your limit. Measured directly: two million tokens on `gpt-5.5-pro` against a `--cost 1` cap, and the request was allowed. The cap read `$0.00`, and would have gone on reading `$0.00` no matter how much you spent.

**Adding an account reset every model family's rotation position.**

Each model family tracks which account it is currently on, independently of the others, so a family that rotated away from a rate-limited account can sit elsewhere while the rest of your pool stays put. A plain `login` overwrote all of those positions with the account you had just signed in, discarding that state as a side effect of adding an account.

**Refreshing an account from the login dashboard switched the account Codex used.**

In `codex-multi-auth login` → Manage → Refresh, the dashboard wrote the refreshed account's new tokens into the native `~/.codex/auth.json` unconditionally. Refreshing account 3 while account 1 was the active one therefore handed plain `codex` account 3's credentials, silently changing which account you were on, with only `Refreshed account 3.` printed.

**Refreshing a disabled account returned it to rotation.**

An account you had deliberately disabled from the dashboard was re-enabled by a refresh, with nothing said about it. Topping up a credential and putting an account back into service are different intentions.

## What's fixed

**A cost budget that cannot be evaluated now fails closed.** Usage summaries carry a count of requests that consumed tokens but could not be priced. While that count is above zero, a `--cost` limit reports `cost limit cannot be evaluated` and blocks, rather than reading unknown spend as free. Priced models are unaffected, and a genuinely breached cap still reports `cost limit reached` as before.

The missing rates are still missing, and this release deliberately does not invent them: a wrong figure would move the trip point and corrupt `usage` output rather than fix anything. What changed is that a cost cap can no longer be silently defeated — it either enforces, or it tells you it cannot. If you route to any of the eight, budget on `--requests` or `--tokens`, both of which cover every model.

| Model | Priced | `--cost` budget |
| --- | --- | --- |
| `gpt-5.2`, `gpt-5.3-codex`, `gpt-5.4`, `gpt-5.5`, `gpt-5.6-sol`, `gpt-5.6-terra`, `gpt-5.6-luna` | yes | enforced |
| `gpt-5.4-pro`, `gpt-5.5-pro`, `gpt-5.2-pro`, `gpt-5.4-mini`, `gpt-5.4-nano`, `gpt-5-mini`, `gpt-5-nano`, `gpt-5.1` | no | blocks with `cost limit cannot be evaluated` |

The eight are now listed explicitly in `UNPRICED_ROUTABLE_MODELS`, with a test that fails if a future model lands in neither the price table nor that list, so the gap cannot widen unnoticed.

**A plain login leaves per-family rotation alone.** A family that was following the global selection still follows it onto the newly added account; a family that had moved somewhere else keeps its own position.

**The dashboard refresh publishes only when it should.** `~/.codex/auth.json` is written when the refreshed account is the one Codex is actually using — which also means refreshing your active account now does update the native CLI, where previously a selection-preserving refresh could leave it on expired tokens. Refreshing any other account leaves the selection alone.

**A disabled account stays disabled through a refresh,** and the dashboard tells you it is still out of rotation.

## New: re-authenticate one saved account

```bash
codex-multi-auth login --account <index|email|account_id> --preserve-selection
```

Refreshes exactly one saved account's credentials. The active selection, every per-family position, and a manual `switch` pin are left where they were, and the write is refused if you sign in as a different ChatGPT account than the one you named — the previous credentials stay intact. Add `--device-auth` on a remote shell. `--account` cannot be combined with `--org`, which would rebind the row to a different workspace.

## Known limitation

The price table covers seven of the fifteen model ids this package routes to. Until the remaining eight have published rates, a `--cost` budget and those models are mutually exclusive: the budget will block rather than under-count. `--requests` and `--tokens` are unaffected and cover every model.
